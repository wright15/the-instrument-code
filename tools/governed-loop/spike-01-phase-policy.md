## 1. T1 — The phase-11 result: derived, lift-consistent

### 1.1 The lemma

Every one of the 462 anchored census masks contains pitch class 0 exactly once
(verified: histogram `{1: 462}`). For a k-note mask transposed by c, the pcSum
shift is the wrap-count identity

```
Δ(c) = c·k − 12·w(c),    w(c) = #{pc ∈ mask : pc + c ≥ 12}
```

For c = 11 and k = 7, w = 6, so Δ = 77 − 72 = **+5**. Equivalently, the
special form is `Δ = 12·n0 − k` with n0 = the number of pitch-class-0 notes;
anchored masks have n0 = 1, giving 12 − 7 = +5.

Verification: the identity holds on all **5,544** mask × phase combinations
(0 failures). Therefore every orbit mean at phase 11 is exactly 36 + 5 = 41:
all 10 orbits verified exactly, in integer arithmetic.

### 1.2 Why this is lift-consistent, not merely transpose-empirical

The admitted candidate record defines phase p as the transposition offset
applied to an anchored record, with node identity `{anchoredId}@{phase}` and
orientation carried inside `anchoredId` (`phase-a-probe.v1.json`,
`p1PhaseCoordinate.definition` and `p4LiftArchitecture.nodeIdentity`). The
lift counts confirm the construction: 462 × 12 = 5,544 heptatonic pairs, every
anchored record contributing 12 nodes, with operator edges lifted fiberwise.
The T₁₁ computation used in §1.1 is therefore the candidate record's own lift
operation, not an external substitute.

Operator semantics are phase-equivariant: 3,402 applications × 12 phases =
**40,824/40,824** checks, calibration EXACT, zero rooting-dependent witnesses.
The carries are exactly `R1 +1`, `L1 −1`, all other operators 0.

## 2. T2 — Cross-phase transition policy

### 2.1 The problem

MVP-1's v0 gate only licenses same-family moves, so the accepted path is
confined to one family (7 states, one office). MVP-2 needs a second license
tier for inter-family and phase-changing motion. The phase data supplies it.

### 2.2 Two-tier transition license (recommended v2 gate rule)

**Tier 1 — within-family.** `governing_root(candidate) ==
governing_root(current)`. The MVP-1 rule. Accept.

**Tier 2 — licensed seam.** A candidate at a different phase (or a different
family) is accepted only if it is the image of a declared lifted operator
application:

- **Family A (operator-realized root-phase seams).** Every admitted R1/L1
  application, lifted at all 12 phases: 420 applications → **5,040 lifted
  edges** (418 cross-family, 2 intra-family). R1 carries `p + 1`, L1 carries
  `p − 1`; the opcode and the phase move together. A candidate is licensed
  iff recomputing the operator on the current lifted node yields it.
- **Family B (bridge-mediated seams).** Shared pentatonic subnodes between
  7-35 and 7-32 heptatonic nodes: **90 crossings over 42 pairs**, phase
  distance 0. Licensed iff the declared bridge route exists.

**No free phase steps.** A candidate that merely differs by ±1 phase is not
licensed. The phase coordinate moves only as the carry of an operator
application, or not at all. This is the load-bearing policy: the phase
machinery is not a free modulation knob.

### 2.3 Gate shape (v2 pseudocode)

```
verdict(current, candidate):
    if candidate not in 462 census:            REJECT not-census-state
    if candidate == current:                   ACCEPT (self, office-supported)
    if governing_root(candidate) ==
       governing_root(current):                ACCEPT within-family
    if is_lifted_operator_image(current, candidate):
                                               ACCEPT licensed-seam (Family A)
    if is_family_b_bridge(current, candidate): ACCEPT licensed-seam (Family B)
    REJECT unlicensed-transition
```

The seam checks must be recomputed from frozen bytes, not read from a
precomputed accept-list; the list is the oracle, not the gate.

### 2.4 Open policy questions

1. Should Tier 2 be evaluated at the seam-edge level (exact lifted edge) or at
   the orbit level (any licensed route within the orbit)? Recommendation:
   seam-edge level first; orbit-level routing is a later policy.
2. Can a boundary record ever be licensed? It has no governing root, so Tier 1
   cannot apply. Recommendation: no, until a separate boundary policy is
   registered; keep the V0-P3 veto.
3. Do Family A and Family B compose (A then B then A)? Recommendation: allow
   composition only through explicit routes; no transitive closure in v2.
4. Should the gate audit an entire accepted path's phase trajectory?
   Recommendation: yes, record-only in v2; see T3.

## 3. T3 — Tier-aware strictness

Measured phase spreads of the per-orbit mean pcSum (max − min over 12 phases,
exact rational arithmetic):

| Tier group | Tiers | Spread | Policy posture |
|---|---|---|---|
| Phase-stable core | A0, A1, A2, D1, D3, D4 | 5.00 | Strict audit; tight drift bound |
| Mid-boundary | D2, D5 | 6.09 | Medium audit |
| Deep boundary | D6 | 10.14 | Loose audit |
| Deepest boundary | D7 | 14.71 | Widest audit; no invariant veto |

Recommended policy:

- **Structural license** (membership, family, seam) is a veto in v2.
- **Phase-relative invariant drift** is a **record-only audit** in v2. The
  audit target is the orbit mean at the reached phase, not a universal 36 or
  41. Flag a path when the observed orbit mean leaves the tier's measured
  spread around the phase-p baseline.
- **Do not promote drift to a veto** without a separate registered policy.
  The 36/41 values are candidate phase-relative constants, not enforcement
  thresholds.
- A-tier strictness is justified by the measured 5.0 spread; D6/D7 tolerance
  is justified by 10.14/14.71. Strictness is a description of the measured
  geometry, not a claim that A-tier behavior is musically preferable.

## 5. Findings that change the roadmap

1. **v0 confinement is real and expected.** The 49% veto rate is a mechanism
   result, not an exploration result. MVP-2 must add Tier 2 before the loop
   can visit more than one office.
2. **Phase motion is operator-carried, not free.** The seam policy above is the
   key design decision; it prevents the phase coordinate from becoming an
   unconstrained knob.
3. **41 is a corollary, not a mystery.** The remaining 41 work is registration
   and lift-carriage, not a proof search.
4. **The pre-registered ±1.0 pp band at n=1000 is statistically underpowered.**
   Use the exact expectation and a z-test; keep the band as a sanity check.
