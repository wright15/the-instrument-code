## 4. Decision resilience: value under a negative result

The framework should be evaluated as several separable claims, not one
all-or-nothing thesis. A negative result for a stronger correspondence claim
does not invalidate independently verified engineering assets.

| Possible negative result | Claim that must narrow or be rejected | Assets that remain useful |
|---|---|---|
| No useful scalar `C_H` can be defined. | A scalar three-coordinate correspondence `C_P ~ C_H ~ C_S`. | Typed harmonic features, CQ/SQ, Hamming geometry, spectral candidates, Forte topology, and explicit unresolved-state handling. |
| `C_P`, harmonic measures, and `C_S` do not correlate. | A cross-domain natural-ordering or common-compression interpretation. | Separate physical, harmonic, and semantic namespaces; the ontology can operate without asserting equivalence. |
| Anchored prompts do not outperform a matched baseline. | The claim that Governor/Court context improves LLM reliability or attention stability. | Deterministic state machines, ledgers, transition guards, validators, and provenance remain valid external orchestration tools. |
| A domain projection produces weak or inconsistent candidates. | The claim that this domain's authored mapping has predictive or generative value. | Other domains, formal topology, compiler interfaces, and abstention rules remain independently testable. |
| A pentatonic class fails one of the seven CRT-310 gates. | Eligibility or necessity of that individual class. | The admitted 5-35 Court, 5-23/5-27 bridges, and every independently evaluated class remain unaffected. |

The minimum durable product is therefore a typed, traceable world-compiler
architecture: ontology, state graph, mutation algebra, deterministic
normalization, Court filtering, provenance, and validation. The stronger
scientific thesis is optional and falsifiable. If it fails, prose and claims
must be revised, but the formal substrate does not need to be discarded.

### GOV-213 research input: the available-tone dictionary

**Disposition:** research candidate for GOV-213 evaluation; not an activated
story, admitted formula, schema change, or non-null `C_H` value.

The available-tone-dictionary insight is a strong description of what the
harmonic layer must expose. A rooted pitch-class set is not only a list of
notes. It defines interval content, scale-step placement, possible subsets and
degree triads, parsimonious moves, symmetry, and other structural affordances.
Those properties can constrain what a compiler or renderer may produce without
inventing semantic content.

The current Court Mathematics model already makes an important notation and
authority distinction:

- lowercase structured `C_h=(H_t,H_v,H_c,H_s)` is an implemented,
  fingerprinted Harmonic Profile;
- uppercase aggregate `C_H` is the reserved total harmonic-compression value
  and remains `unresolved` with `value=null`;
- computing or collecting component measures does not silently totalize them.

The dictionary insight therefore strengthens the interpretation of structured
`C_h`. It supplies candidate inputs for GOV-213, but it does not by itself
resolve whether a useful scalar uppercase `C_H` exists.

#### Formal carrier and scope

For a rooted scale `R=(S,r)` in 12-TET, let `S` be the pitch-class set and `r`
its declared root. The implemented structural dictionary can be written as:

```math
D_H(R)=C_h(R)=(H_t,H_v,H_c,H_s),
```

where:

- `H_t` contains the interval-class vector, rooted cyclic steps, semitone and
  tritone counts, and leading-tone descriptors;
- `H_v` contains exact voice-leading affordances under a named metric;
- `H_c` contains dyad/trichord incidence and ordered degree-triad inventory;
- `H_s` contains Forte-class, prime-form, and symmetry descriptors.

This is the inspectable dictionary of what the rooted harmonic state permits.
An aggregate candidate, if one is useful, is a separately versioned projection:

```math
C_H^{(m)}(R)=N_m\!\left(\phi_m(D_H(R))\right),
```

where method `m` must declare its scope, tuning, selected inputs, exact weights,
normalization `N_m`, invariances, covariance behavior, collisions, and failure
cases. The existence of `D_H` does not guarantee that any projection `phi_m`
preserves enough information to deserve the name `C_H`.

#### Interval-density candidate and its hard limit

A weighted interval-content score is a valid candidate family descriptor:

```math
E_delta(S)=\sum_{k=1}^{6} delta_k v_k(S),
```

where `v_k(S)` counts interval class `k`. The interval vector is objective for
the declared pitch set; the weights `delta_k` and the interpretation of the
result are authored method configuration. Unless a sourced psychoacoustic
model with units is used, this value should be called a **weighted
interval-content score**, not physical energy.

This score has a decisive limitation only when used by itself. Every rooted
mode of Forte 7-35 has the same interval vector:

```text
(2, 5, 4, 3, 6, 1)
```

Consequently, every fixed weighted-interval formula gives the same value for
Lydian, Ionian, Mixolydian, Dorian, Aeolian, Phrygian, and Locrian. Changing or
learning those six interval-class weights cannot make an interval-vector-only
score distinguish those modes.

This is not a limitation of a rooted Governor profile. Once one common tonic
phase is fixed - represented in the repository by normalizing the declared
root to pitch class 0, equivalent to comparing all profiles at a common key
such as C - the placement of intervals, tertian triads, and other affordances
among scale degrees remains observable. Transposing every state and its root
together should preserve that rooted profile, so the method depends on relative
phase rather than privileging the absolute pitch class C.

Mode-sensitive evaluation requires rooted information. The seven 7-35 states
have distinct cyclic step sequences, each a rooted rotation of the diatonic
pattern. A minimal exact candidate packet is therefore:

```math
F_H(R)=(v(S),d(R)),
```

where `v(S)` is the family-level interval vector and `d(R)` is the rooted
seven-entry cyclic step sequence. The full implemented `C_h` adds chordal,
voice-leading, and symmetry affordances. Rooted phase distinguishes the seven
modes, but distinction alone does not prove a tension or compression ordering;
that ordering remains a separate hypothesis.

#### Verified A0-A2 rooted-triad candidate theorem

The complete theorem, 21-state audit table, exact signatures, score values,
scope guards, and admission path are retained in
`docs/A_TIER_TRIADIC_COMPRESSION_THEOREM.md`. The summary below keeps the
result connected to GOV-213 planning.

The supplied A-tier theorem was independently reproduced from
`canonical/universal-heptatonic-ledger.json` with source SHA-256
`e6570972260fdae5c4ca878272dc89a9ff353d48762eefbe019707d229cd242d`
and the existing `DegreeTriad` derivation. Its finite structural claims hold
over exactly 21 records selected by both conditions:

```text
role = anchor
tier in {A0, A1, A2}
```

Filtering by tier alone is insufficient because satellites and other records
also carry A-tier labels.

For each rooted heptatonic state `S`, derive the seven degree-stacked tertian
triads. The runtime records each signature as `(0, third, fifth)`; the notation
below omits the leading zero. Define the authored ordinal encoding `q_v1`:

```math
q(4,7)=0,\qquad q(3,7)=1,
```

```math
q(3,6)=q(4,8)=2,
```

```math
q(2,6)=q(4,6)=3.
```

These values encode major, minor, diminished/augmented, and two exotic
scale-generated tertian signatures, respectively. Diminished and augmented
remain different harmonic objects even though `q_v1` places both in class 2.
The two exotic signatures remain runtime quality `other` even though `q_v1`
places both in class 3. The class numbers are ordinal framework configuration,
not physical or psychoacoustic energy.

Define the rooted Triadic Compression Signature:

```math
Q(S)=\left(q(\tau_1(S)),\ldots,q(\tau_7(S))\right).
```

The admitted Chaldean degree map is:

```text
Degree:           1       2        3     4    5      6        7
Degree Governor:  Saturn  Jupiter  Mars  Sun  Venus  Mercury  Moon
```

Let `d(G)` be its inverse. For every one of the 21 selected anchors with
already-resolved State Governor office `G`:

```math
q\!\left(\tau_{d(G)}(S)\right)=2.
```

This is a 21/21 Governor-seat consistency result. It checks an existing office
assignment; it does not infer an unknown State Governor from a Degree Governor
or from an `argmax` operation. A0 and A2 carry diminished triads at the selected
degree, while A1 carries augmented triads there.

Each anchor family also has one mode-invariant multiset:

| Anchor family | Triadic compression multiset | Unweighted sum |
|---|---|---:|
| A0 / 7-35 | `{0,0,0,1,1,1,2}` | 5 |
| A1 / 7-34 | `{0,0,1,1,2,2,2}` | 8 |
| A2 / 7-33 | `{0,1,2,2,2,3,3}` | 13 |

The modes differ in degree placement rather than multiset content. The strict
unweighted tier relation `5 < 8 < 13` is therefore structurally reproduced
under `q_v1`. The fact that these are consecutive Fibonacci numbers is
`CH-OBS-001`, status `observed_noncausal`; it follows from this authored
encoding and carries no physical or universal-growth claim.

Define a theorem-local weighted projection in degree order `(1,...,7)`:


subject to the authored Chaldean hierarchy:

```math

```

The exact feasible witness is:

```math

```

This witness reproduces the intended A0 ordering and strictly separates the

| Tier | Minimum | Maximum |
|---|---|---|

```math
<\frac{349}{407}\le W(A1)\le\frac{574}{407}
```

The exact A0 order is:


The LP establishes existence of a weight vector satisfying the declared

establish that those authored constraints are uniquely necessary. The displayed

The theorem therefore supports a scoped candidate:

Within that scope, `Q(S)` is a rigorous rooted seven-dimensional signature and

Global extension must be revised or rejected if later audits find that the
encoding cannot cover new triadic signatures, no positive Chaldean-ordered

#### GOV-213 candidate evaluation gates

1. **Scope:** Declare tuning, cardinality, root convention, state/family/pair
   scope, output kind, and intended interpretation.
2. **Derivation:** Recompute the pitch set, interval vector, rooted steps, and
   affordances from existing canonical types; reject inconsistent authored
   copies.
3. **Negative control:** Demonstrate that weighted interval content produces
   one seven-way collision across the 7-35 modes.
4. **Modal discrimination:** Require any mode-sensitive candidate to expose a
   rooted component that distinguishes all seven A0 fixtures without using
   Governor office as an input.
5. **Invariance and covariance:** Prove input-order independence and joint
   transposition invariance; show declared modal rotation under `M` and closure
   under `M^7`.
6. **Collision analysis:** Evaluate all 462 rooted heptatonic states and publish
   collision classes, including Z-related counterexamples, instead of tuning
   weights to hide them.
7. **Weight and normalization provenance:** Use exact versioned configuration;
   do not fit weights directly to reproduce office index, `C_P`, or `C_S` and
   then cite that fitted agreement as independent evidence.
8. **Operator behavior:** Measure candidate deltas under all 15 structural
   operators and preserve route-independent intrinsic results wherever
   confluence is required.
9. **Namespace safety:** Reject equality or substitution with `C_P`, `C_S`,
   `kappa_court`, photon energy, temperature, entropy, enthalpy, or free energy.
10. **Determinism and admission:** Use canonical float-free serialization,
    golden fixtures, counterexamples, and two-build identity. Promotion requires
    a new versioned schema/release and an explicit GOV-213 decision.

#### Interpretation boundary

The proposed through-line should be stated as a testable architecture, not an
already established causal law. `C_P` supplies a separately typed photonic
coordinate; `D_H` supplies discrete harmonic constraints; `C_S` supplies an
authored semantic ordering. A renderer can be required to obey both harmonic
and semantic constraints after each is independently admitted. High weighted
interval content does not by itself mandate aggression, prove Mars semantics,
or show that light energy was converted into music. Likewise, the dictionary
constrains what a tool may generate only when the runtime explicitly enforces
it; it does not physically dictate an AI's output.

The insight remains valuable under these guards: it identifies structured
`C_h` as the inspectable gearbox of available musical operations while leaving
the aggregate `C_H` formula and any `C_P`/`C_H`/`C_S` correspondence open to
falsification.

### Six-step domain gate

Every new domain must:

1. define its ontology;
2. encode canonical relations;
3. declare projection rules and source classes;
4. run intrinsic and route-aware confluence tests;
5. review generated outputs against deterministic artifact specifications;
6. record failures and revise the responsible formal layer.

Each domain story must also evaluate all 15 admitted structural operators. For
each operator, the domain contract must either declare source-backed semantic
effects with fixtures or retain an explicit unresolved disposition. Adding a
domain does not authorize filling every effect slot by analogy. If a future
registry version introduces a `by_domain` map, that map must preserve the same
per-operator evidence and abstention rule.

3. At least one Phase 7 domain passes the six-step domain gate.
4. Domain-specific effects cannot mutate canonical intrinsic fields.
5. Exact match, partial match, no match, conflict, and unresolved outcomes are
   distinct and tested.

### Experimental minimum

1. Freeze model, inference settings, tool permissions, initial context, task
   corpus, and environment fixture.
2. Compare at least an unanchored baseline, a plain structured-state baseline,
   and the full Governor/Court anchor. This separates the value of ordinary
   state serialization from framework-specific topology.
3. Score outcomes without using framework language as the scoring criterion.
4. Include successful, failing, recovery, and abstention tasks.
5. Publish complete prompts, state traces, environment evidence, and scoring
   code when licensing and privacy permit.
6. Treat no benefit or worse performance as a valid result.

### Epic exit criteria

1. Initial success criterion 18 has a reproducible result, positive or
   negative.
2. Claims about attention, reliability, or recovery are no stronger than the
   measured evidence.
3. The artifact compiler remains authoritative over generated prose.
4. A prototype can reject an invalid rendering and explain the violated field.
5. Runtime complexity added by the twelve-node model is justified against the
   plain structured-state baseline.

GOV-226 is intentionally downstream of formal and domain validation. It is the
first candidate for demonstrating practical value in worldbuilding, game
development, or constrained generative content, but user interest is not a
substitute for artifact-spec fidelity or empirical evidence.

## 12. Governance guards for all four frontiers

- Framework prose is not proof of physical, harmonic, semantic, graph, or
  runtime truth.
- A proposed epic cannot weaken current namespace separation or abstention.
- New domain mappings must distinguish empirical facts, authored
  correspondences, generated interpretations, and unresolved fields.
- A renderer may express an Artifact Specification but cannot redefine it.
- A positive LLM result does not prove a transformer-circuit mechanism unless
  the experiment measures that mechanism.
- A negative LLM result must be published with the same fidelity as a positive
  result.
- CRT-310 classes advance individually; family resemblance and aggregate
  statistics are not admission evidence.
- Frozen packages remain immutable. New versions or root-owned extensions are
  required for admitted changes.
- Every deterministic claim requires two-build or equivalent reproducibility
  evidence and release-manifest closure.

## 13. Pre-EPIC-400 exit condition

   that choice?

The next implementation epic should be selected from those answers, not from
the symbolic appeal of the framework or the numerical order of the planning
handles.
